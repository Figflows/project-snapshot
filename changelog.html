Changelog — Project Snapshot for Jira

Format: version, date, then Added / Changed / Fixed / Security. Scope, egress or storage changes will always be called out under Security and treated as major versions.

1.3.1 (security fixes for Marketplace review) — 2026-10-29

No scope, egress or storage change. 102 unit tests.

Security

  • Run check now (snapshot policy) now runs as the Jira administrator who clicked it (asUser()), after the server-side Administer Jira check. Only the weekly scheduled check, which has no signed-in user, still runs as the app. Raised by Atlassian's Forge security scan (FSRT authorization check).
  • Runtime dependencies updated (Forge packages; patched versions of undici and prosemirror-view). npm audit reports no vulnerabilities in the shipped code.

1.3.0 (Marketplace release build, listed on the Marketplace as version 2.0.0) — 2026-09-30

Fixes from a third, independent review of the 1.3.0 development build; this is the build submitted to the Marketplace. 101 unit tests. No scope, egress or storage-scope change.

Fixed

  • ZIP writing is now serialised across the parallel download lanes, so a file can no longer be missing from a part's manifest or land in the wrong part; a part also closes at 60,000 files (the ZIP format without ZIP64 cannot hold more), not only at the chosen size.
  • Complete snapshot rule: only an export in mode Everything, without a JQL filter, not incremental, on a licensed site, with zero errors, updates the Coverage date, satisfies the policy or serves as the incremental baseline. All other exports stay in Previous snapshots marked "(partial)".
  • The incremental cut-off is written in the user's Jira profile time zone (with a one-hour margin; 26 hours if unknown), so a profile time zone different from the browser's can no longer skip issues.
  • A run stops as Failed after 25 consecutive item failures or when a search page returns 401/403, instead of finishing "Done" with thousands of errors; the Done line, the manifest and the log count issues actually written.
  • Sample mode caps on the issues actually returned, never on the estimate (a low estimate could export nothing).
  • Reminder tasks created by the weekly run now link to the project's export page (the page ids are stored when an admin saves the policy); duplicate detection no longer breaks on project names with quotes.
  • The Ignore these projects field accepts typing (free text, tidied on save).
  • Cancelled requests no longer print errors to the browser console.
  • JQL filters with unbalanced parentheses or quotes are refused before the run; a multi-line ORDER BY is stripped correctly.

Changed

  • The progress panel lists saved parts only, the pre-run hint says that the first part downloads automatically and later parts need a click, the browser warns before the tab is closed during an export, and a failed write to the snapshot log shows a red banner.
  • Previous snapshots show the mode as "Everything" / "Attachments only"; Coverage links to product-discovery projects correctly; policy errors are shown as a list; the Apps page lead text mentions the Policy tab.
  • Accessibility: screen readers hear phase changes only (not every issue), tabs announce their panel, table headers are marked up.
  • npm run deploy:dev / deploy:prod run the checks and the build before deploying.
  • Removed the unused latest resolver; the app reads the history and picks the newest complete record.

1.3.0 (development build) — 2026-09-29

Forge app version 4.x (major, because a scope was added). 78 unit tests at release. Deployed to the development environment and live-tested on the developer site on 2026-09-29.

Added

  • Snapshot policy — a fourth tab, Policy, on Apps → Project Snapshot, for Jira admins: switch on "every project needs a snapshot no older than 30 / 60 / 90 / 180 / 365 days", include or exclude never-exported projects, choose a reminder project (dropdown), "Assign reminder tasks to me", an ignore list of project keys, Save, Run check now and a last-run summary.
  • Weekly check (Forge scheduledTrigger, licensed sites only): compares the snapshot log with the project list remembered from the last admin visit to Coverage or Policy, flags projects behind the policy, and — only if a reminder project is chosen — creates one Jira task per project: summary Snapshot due: KEY (name), label project-snapshot-reminder, description with the reason and a link to that project's export page, optional assignee. At most 20 tasks per run; no duplicate while a task for that project is open. Jira's own notifications inform the assignee; the app sends no e-mail.
  • Coverage and Policy pages remember the project list (id, key, name, type) in app storage so the check, which runs without a user, knows which projects exist.

Changed

  • App version string in manifest.json / README.txt inside exports is now 1.3.0.
  • The Coverage and Policy tabs send the project list they display to the app's storage (rememberProjects) on every visit.

Security

  • New scope write:jira-work, used by exactly one function (the policy check) for exactly one operation: POST /rest/api/3/issue in the chosen reminder project, only while the policy is on and a reminder project is set. No other write anywhere; with the policy off the app behaves as 1.2. Justification in the Marketplace Privacy & Security tab and at https://figflows.github.io/project-snapshot/data-handling.html.
  • The policy check calls Jira as the app (asApp()) because it runs on a schedule without a user: create the reminder task, read the status of a task it created earlier, search the reminder project by label, read serverInfo and the reminder project's issue types. It reads no issue content of the projects it checks.
  • Changing the policy and running the check by hand require the Jira global permission Administer Jira, verified server-side (mypermissions?permissions=ADMINISTER); the form is hidden from other users.
  • New storage keys, metadata only: policy, policy:lastRun, projects (id, key, name, type), reminder:<projectId> (issue key). Still read:jira-work for all exports, still no egress permissions, no remotes, no external hosts, no e-mail. Runs on Atlassian eligibility confirmed by Forge on the 4.x development deploy.

Known limitations

  • The check only knows projects that an admin's Coverage or Policy visit remembered; open one of those tabs after creating projects.
  • The reminder project needs a standard, Task-like issue type without required custom fields on its create screen, and the app must be allowed to create issues there; errors appear in the last-run summary.
  • Closed reminder tasks are not reopened; a project still behind the rule at the next run gets a new task.
  • The check does not run in sample mode (unlicensed sites).

Release summary for Marketplace (≤ 80 chars): Snapshot policy: weekly check flags stale projects, creates reminder tasks.

1.2.0 — 2026-09-29

Forge app version 3.2.0 (minor: no scope, egress or storage-scope change). 73 unit tests. Live-tested on the developer site on 2026-09-29.

Added

  • Readable HTML archive in every full export: index.html (sortable, searchable list of all issues; inline script only, no external resources) and issues/<KEY>.html per issue with fields (custom field names resolved from project.json), description, comments, worklogs, change history, links and links to the attachment files. Opens offline in any browser. Optional (on by default); not produced in Attachments only mode.
  • Incremental export on the project page: "Incremental: only issues updated since the last snapshot" adds updated >= (last snapshot − 1 hour) to the JQL; README.txt and manifest.json are marked INCREMENTAL. Keep incremental ZIPs together with the full snapshot they extend.
  • Verify a snapshot tab on Apps → Project Snapshot: choose one or more downloaded ZIP parts; every file's presence, size and SHA-256 is checked against the part's manifest.json in the browser; result Verified or Mismatch with the reason per file. Nothing is uploaded.
  • Previous snapshots panel on the project page: history from the snapshot log (date, mode, counts, size, parts, manifest hash), Download evidence CSV, Delete log for this project.
  • Download coverage CSV on the Coverage tab.

Changed

  • App version string in manifest.json / README.txt inside exports is now 1.2.0; the manifest records whether the HTML archive was included and whether the export was incremental.
  • The in-app "what you get" list mentions index.html.

Security

  • Scopes unchanged: read:jira-work and storage:app. No egress permissions, no remotes, no external hosts. Runs on Atlassian eligibility confirmed by Forge on deploy of 3.2.0.
  • HTML archive: all issue content is escaped; links limited to http(s) and mailto; no external resources.
  • Verification and CSV generation run entirely in the browser.
  • Resolver gains latest (most recent record of a project, for the incremental option; removed again after 1.3.0 — the UI now uses history) and deleteProjectLog (removes a project's log records on request). Still no Jira calls, never any issue content.

Known limitations

  • Incremental exports do not detect issues deleted since the previous snapshot.
  • Incremental is available for project exports only, not for Export by JQL.
  • Verifying very large parts takes time; every byte is hashed in the browser.

Release summary for Marketplace (≤ 80 chars): Readable HTML archive, incremental exports, verify tool, snapshot history CSVs.

1.1.0 — 2026-09-29

Forge app version 3.0.0 (major, because a scope was added). Live-tested on the developer site on 2026-09-29.

Added

  • Apps → Project Snapshot global page with two tabs.
  • Coverage tab: every project the user can see with its most recent snapshot (date, issues, attachments, size); projects flagged Never exported or Stale after a chosen threshold (30 / 90 / 180 / 365 days), with counts, a filter and an Open button to the project's export page.
  • Export by JQL tab: export any bounded JQL query as Everything (per-issue JSON with comments, worklogs, change history, links, attachment files) or Attachments only (attachment files plus an issues.csv index).
  • Attachments only mode on the project settings page.
  • Snapshot log: after each finished export a small record (project id/key/name, mode, timestamp, account id of the person who ran it, counts of issues/attachments/bytes/parts/errors, manifest SHA-256, sample-mode flag, JQL) is stored in Forge Key-Value Storage. No issue content, comments or attachments. At most 50 records per project; older ones are deleted automatically.

Changed

  • Sample mode unchanged (25 issues, no attachments); Attachments only is disabled in sample mode.
  • App version string in manifest.json / README.txt inside exports is now 1.1.0.

Security

  • New scope storage:app, used only for the snapshot log. Forge-hosted storage is inside the customer's Atlassian site and follows its data-residency location; Atlassian removes it after uninstall per Forge's retention rules.
  • Still read:jira-work for Jira. Still no egress permissions, no remotes, no external hosts. Runs on Atlassian eligibility confirmed by Forge on deploy.
  • One Forge resolver function (src/index.js) writes and reads the log; it makes no Jira calls and never receives issue content.

Known limitations

  • The log started with 1.1.0; exports made with 1.0.x are not in it, so those projects show as never exported until exported again.
  • Deleting individual log records from inside the app is not yet possible (uninstall removes the log). Per-project deletion was added in 1.2.0.

Release summary for Marketplace (≤ 80 chars): Export any JQL, attachments-only mode, snapshot log and coverage overview.

1.0.0 — 2026-09-29 (internal, never published)

Initial release.

Added

  • One page under Project settings → Project Snapshot for project admins.
  • Complete export of one Jira Cloud project: every issue with all fields, comments, worklogs, full change history, issue links, attachment files, and project configuration (issue types, statuses, components, versions, roles, link types, field definitions).
  • Output as ZIP parts built in the browser: project.json, issues/<KEY>.json, attachments/<KEY>/<id>-<filename>, issues.csv, errors.json, manifest.json with SHA-256 per file.
  • Part size selector: 250, 500 or 1000 MB.
  • Optional JQL filter.
  • Cancel button; parts already written are kept.
  • Automatic back-off and retry on Jira rate limiting (HTTP 429).
  • Sample mode when unlicensed: first 25 issues, no attachments.

Security

  • Scope: read:jira-work only. No write scope, no user scope.
  • No backend, no Forge storage, no egress permissions, no remotes. Eligible for Runs on Atlassian (forge eligibility output attached to the release).
  • All API calls run as the signed-in user.

Known limitations

  • The export runs in the browser tab; closing the tab stops it.
  • No restore into Jira.
  • Every part is an ordinary browser download (the app cannot choose a folder). Tested in Chrome and Edge; Firefox and Safari not yet verified.

Release summary for Marketplace (≤ 80 chars): Initial release: complete per-project export to ZIP, built in the browser.
